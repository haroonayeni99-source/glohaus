## Verified bugs fixed

- Choosing a discovery area replaced the selected service/category, and vice versa. Filters now preserve each other through search, map controls and pagination.
- A successfully published review could leave its form busy without confirmation. Publishing now clears busy state, confirms success and prevents duplicate submissions.
- A rejected booking transition was reported as a service outage. Known database decisions now return permission/conflict responses; unknown failures remain redacted.
- A previous user filter could hide an account chosen in global Owner search. Selecting a global result clears local filters, reveals the correct section and scrolls to the account.
- Public landing/discovery pages inherited the same noindex default as private workspace pages. Public metadata is explicitly allowlisted while internal pages retain the safe default.

Public-server checks explicitly clear database/auth configuration. Fixture servers use fictional data and intercept mutations; they must never be presented as authenticated production verification.

The complete unit/integration suite passed: **578 tests in 66 files**. Lint, TypeScript and the production build passed. The production-mode desktop/mobile Playwright suite passed **36 tests**. Earlier development-server runs suffered resource/connection failures; the final checks run the built server with two workers. A local Turbopack cache corruption was resolved by rebuilding the generated cache from scratch; source and dependency versions were unchanged.

## Launch handoff

- In the Google account that owns the domain, verify the Search Console property and submit `https://www.glohaus.shop/sitemap.xml`. No Google ownership token or DNS secret was read or changed. Indexing depends on Google's crawl after deployment.
- External authentication-email delivery, provider verification and real bank/payment settlement require approved provider test accounts or a supervised real-user trial. Existing rules and live balances were preserved.
- Coordinate-backed distance and live street-map results need verified location data; the current illustrated area guide does not claim exact distances.
- Monitoring watches new production errors and failed Resend events. It reports actionable findings and makes no automatic production mutations.
