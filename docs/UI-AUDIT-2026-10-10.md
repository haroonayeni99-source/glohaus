# GLOHAUS Owner/Admin and conversation audit — 10 October 2026

This release addresses customer/professional conversation history, light/night presentation, Owner/Admin navigation and control failures, and easier image editing. “Both parties” means the participants in a conversation. It does not grant administrators access to private chats.

## Verified problems and fixes

- Conversation history required repeated page loading; empty conversations stopped polling; new replies could pull readers away from older messages. Added **View full conversation**, clear participant labels and timestamps, empty-thread polling, retryable history loading and stable reading position.
- The professional message workspace imposed dark surfaces in light mode. Scoped chat surfaces, text and controls now follow the selected theme. Owner/Admin totals, buttons, labels and referral rows also had theme contrast problems; corrected those surfaces and foregrounds.
- Sidebar highlights used menu order rather than section positions. Smooth scrolling and same-row cards changed the selected item after clicks; sticky headers obscured targets. Navigation now uses actual positions, keeps explicit selection until scrolling, and accounts for header height. Added an expandable icon rail on desktop and a **Go to section** picker on mobile.
- Admin saw Owner-only overview shortcuts. Overview now leads the page, reflects the account's role and links only to available sections. Search filters out inaccessible or absent targets and works on mobile.
- Optional SQL failures could abort the transaction carrying the core dashboard data. Optional overview queries now run in separate authenticated transactions. Unavailable sections keep their navigation targets and show retry controls instead of disappearing or displaying successful zero totals. Mandatory failures reach a retryable error boundary.
- Moderation and management buttons opened a form without directing attention to it. They now scroll to and focus the decision form. Existing restriction dates are retained correctly in local time. Expired security verification and access errors give actionable instructions.
- Feature-vote publishing used the event's expired `currentTarget` after an asynchronous request, producing an error after success. The form is captured before awaiting the request.
- Production database inspection confirmed **two functions referenced the nonexistent `beauty.owner_audit_log` table**: homepage-image saving and marketing preset launching. Their writes rolled back. The migration replaces only those audit inserts with the existing protected `beauty.write_admin_audit` writer. Authorization, validation, campaign selection, queueing and permissions are retained.
- Homepage changes previously required image URLs. Added desktop/mobile file selection, private previews, Save and default restoration; advanced URLs remain available. Uploads use the existing private Blob store, image sanitizer and Owner/MFA protections. Public image delivery is restricted to the currently published homepage paths; unpublished previews require Owner access.
- Professional image editing now previews the selected file before saving, supplies editable alternative text, and immediately reflects successful save/removal while retaining the existing permission acknowledgement.
- The professional referral campaign pointed at a missing destination. `/professional/referrals` now reaches the existing referral panel. Shop's existing Cart destination is now visible in its actions.
- The inactive Staff permissions button is replaced with an explanation. Administrator access remains available; granular staff access remains disabled pending an existing permission-aware workspace. This release does not introduce new role rules.

- **34 Playwright foundation tests pass**, including guest navigation, cart access, theme persistence, authentication safeguards and professional referral routing.
- Layout matrix: 16 Owner/Admin role/theme/width cases and 8 customer/professional conversation cases. No detected missing navigation targets, duplicate IDs, horizontal overflow, incorrect click highlights, covered section targets or browser exceptions.
- All-optional-failure fixture: 20 retry controls appear with every navigation destination retained.
- Control matrix: eight Owner/Admin role/theme/width combinations exercise 188 locally intercepted mutation requests. Four professional-photo cases exercise select/preview/save/removal. An expired-MFA case verifies the Security recovery message/link. These are isolated interaction checks, not production mutations.
- Solid-background contrast scan: no failing text samples in the tested Admin/chat light/night cases. Gradients are excluded from the computed scan; this is not a whole-site accessibility certification.
- Isolated Postgres-compatible integration tests first reproduce both missing-table failures and rollback. The migration then passes all 14 preset cases, opted-in recipient selection, audit logging, homepage save, invalid-input rollback and Owner/MFA denial tests.

## Production scope and limits

The database change replaces two existing function bodies only. The deployed functions' original ACLs, `SECURITY DEFINER` setting and `search_path=pg_catalog` are checked before and after the migration. The general migration runner is not used: legacy repository/database migration history differs, and its drift guard remains intact.

Signed-out production access is checked separately from the local authenticated-role fixtures. No signed-in production Owner/Admin browser session is available, so the full live authenticated workflow cannot be claimed as verified. Real email delivery, refunds, payments, account deletion and role/rate changes require an appropriate authorised live exercise. Existing bounded account listings remain bounded; pagination of every management table is outside this release. Private unsaved/replaced image uploads are retained rather than deleted. Granular staff permissions remain unavailable as explained above.

Supabase security-advisor baseline includes existing function-mediated private-table policy notices, the intended public site-status function and disabled leaked-password protection. Those settings are outside this release; no auth or secret configuration is changed.

This audit covers the listed page controls and reported symptoms. It does not assert that every possible site bug has been eliminated.
